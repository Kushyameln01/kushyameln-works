# Model-connection design review

Reviewed 2026-11-04. Read-only review of `work/lora-implementation/development/lora/model-connection/{DESIGN,PLAN}.md` against the fixed owner sources under `work/lora/integration-20261104/{diffusion,manager}` and the existing standalone implementation. No implementation, original LoRA transfer, NN execution, arithmetic-proof rerun, or approval request was performed.

## Result

The proposed canonical registry, immutable base provider, owned-package consumer, and epoch-fixed completed-source adapter are implementable with the current APIs. No API redesign is needed for Task 1 or management integration. One native constructor cleanup limitation must remain explicit: the fixed owner cannot provide retryable cleanup after its constructor itself fails cleanup. This limits the session cleanup guarantee; it does not block the F32 port implementation.

## Material finding: native preparation cleanup cannot always be recovered by session glue

`diffusion/docs/shared/diffusion-models/execution/model-candidate.mjs:331` catches preparation failure and invokes its private cleanup. If cleanup also fails, it throws an `AggregateError` without a model handle or recovery callback. The session factory therefore has no native handle on which it can retry `dispose()`/`recover()`. A control constructor that exposes retryable cleanup cannot establish that behavior for this fixed native constructor.

For successfully returned models, the proposed terminal → native disposal → source lease release sequence is supported: `model-candidate.mjs:94-104` aborts active work, waits for its terminal promise, and retries retained cleanup on subsequent disposal calls. Supplied source/math/ops remain caller-owned. For failed construction, distinguish an ordinary constructor rejection whose cleanup completed from the owner's preparation-and-cleanup failure. Preserve the source lease/recovery-pending record when native cleanup is unconfirmed; do not report all native resources recovered or discard the lease as if native disposal succeeded. If complete native preparation recovery is required, the owner needs an explicit retained recovery capability. That owner guarantee cannot be manufactured solely in the proposed adapter.

## Implementation rulings from current code

1. **Registry shape and bindings are compatible.** A direct Node import comparison of the two existing target tables produced 1,095 owner targets, 1,053 eligible 1D/2D weight/bias targets, and zero key/shape mismatches. Eligible targets comprise 406 2D runtime-input bindings and 647 1D Hike parameter bindings. The 42 excluded targets are exactly `blocks.0..39.modulation`, `head.modulation`, and `patch_embedding.weight`. Keep the standalone registry's strict logical shape (`standalone-registry.mjs:17-35`); expose owner binding/operator metadata through a separate binding table, because adding these fields to standalone targets causes registry validation failure. Preserve all 1,095 entries in the completed source's description. A 1,053-entry description cannot pass native `sourceIdentity` (`model-candidate.mjs:43-52`).

2. **Split package reads to owner limits.** `owned-package.mjs:10,146-149,171` permits at most 1,048,576 F32 elements and requires complete rows for matrices. `model-weights.mjs:10,37-44` caps owner reads at 81,920 elements and per-target `maxRows` (at most 16). For `blocks.N.ffn.2.weight` with width 13,824, only 5 rows fit. Default package `blocks({blockRows:16})` therefore cannot be forwarded as a single owner `readRows` call. The base provider must split valid package blocks into sequential owner reads respecting both limits, or validation must select sufficiently small blocks while the general provider still supports its advertised contract. Source reads are single-flight; old and current capture leases must serialize shared-source access or explicitly reject overlap without corrupting ownership.

3. **The package returns final F32, not a delta.** `createCompletedModelWeightSource` (`model-weights.mjs:127-151`) first reads and decodes the immutable source, then invokes `completedProvider.readBlock` with `baseValues`. Its callback result replaces the base values; null/undefined passes the base through. Existing package `readBlock` independently reads the base provider and applies light/detail (`owned-package.mjs:149-167`). With the existing API unchanged, a patched read may decode/read base twice. That is a performance property, not permission to add the returned package values to base or to apply scale again. Use null for excluded/unselected ranges; for overlapping selected rows, package `readBlock` preserves unselected rows and provides final values. No F16/FP8 decoding or arithmetic belongs in this adapter.

4. **Retain capabilities independently at every lifetime boundary.** Package `retain(ownerId)` returns another package capability directly (`owned-package.mjs:174-177`), with `readBlock`, `blocks`, `isValid`, and asynchronous `release`. Prepare, active publication, rollback predecessor, and captured source lifetimes must not depend on the caller's prepared handle. A captured lease can remain valid after management releases prepared SDK packages. Package release waits for in-flight package use, but the completed source's `dispose()` merely rejects busy and marks itself disposed; it neither releases packages nor disposes the underlying source (`model-weights.mjs:156-157`). Capture release must await its complete read terminal, then dispose its wrapper and release its own package capability; retain failed releases for retry. Base source remains caller-owned and must outlive captures.

5. **Normal admission must return the precise existing receipt fields.** Manager `adapter.mjs:75` calls `sdk.stage(..., {validationMode:'normal', isCurrent, signal})`. Standalone `standalone-sdk.mjs:106-129` requires matching contractVersion, planId, packageHash, registryHash, coverage, scope, and validationMode in validation/commit receipts, a safe integer epoch, and valid lease/independent-copy ownership. `consumer.currentEpoch()` must agree with the commit receipt. Normal validation may stream all selected blocks for finite/range/identity/current checks; independent expected values, numerical diagnostic gates, detailed hash receipts, and NN calls are not required. An empty selection is valid base restoration and still needs publication/epoch semantics.

6. **Atomic publication and rollback need candidate identity, not just revision.** SDK invokes rollback even when prepare failed before returning a candidate, and after a successful commit if later receipt/current/release checks fail. Rollback of undefined must be harmless. Retain the predecessor until candidate release after successful SDK receipt acceptance. Restore it only if the candidate still owns the active publication. An old candidate rollback must never restore over a later publication, and cleanup failure must remain retryable. Check abort/current/base identity/epoch again at publication; do not await between the final check and the synchronous pointer/epoch change. SDK local revision, manager revision, and consumer epoch are separate counters, as planned.

7. **Session checks must surround awaits and cover cached reads.** `model-head.mjs:45-60` retains loaded head weights/bias/modulation across runs. A completed source that changes dynamically cannot update that cache. The proposed fixed capture plus stale-session rejection is correct. Check the captured epoch after awaiting model construction, before native calls, and after native calls before accepting output. An active operation may finish against its immutable old capture, but the wrapper must not accept that result as the new epoch. Wrapping only source reads is insufficient because cached head work may perform no reads. Disposal must remain callable on a stale session. Do not expose the raw model as an unguarded route that bypasses these checks.

8. **Native option forwarding and scope must stay explicit.** `createBerniniModelCandidate` (`model-candidate.mjs:72-84`) rejects `source` combined with `file`, `side`, `bridgeBytes`, explicit decoder/lookupBytes/readAheadBytes and rejects unknown option names. The session owns the supplied `source` option; reject conflicting options before capture or release it on validation failure. A real owner constructor exercised with injected control math/ops can prove constructor/source/cleanup integration without a whole NN experiment. It cannot establish NN numerical behavior or public sample adoption. The design already correctly identifies that public Worker/model-adapter/sample wiring still lacks this path; keep that as an explicit remaining implementation scope rather than labelling port completion as public sample completion.
