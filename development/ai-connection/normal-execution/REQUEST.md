# 今回の要求と受入範囲

2026-11-02 JST。直近のユーザー指示を実装の正本として固定する。

通常の受け渡しは、既存descriptorの操作・使用モデル／対象・shape・dtype・軸・意味・正規化状態と、ownerが返す実行能力／理由で判断する。管理独自の固定Profile一覧や、workflowの式への適合だけでは実行を許可しない。

独立数値参照・誤差gate・事前PASS・数値receipt・全中間E4保存は通常入口の必須条件から外し、従来の診断入口を維持する。既存の判定・queue・snapshotを再利用する。

サンプルworkflow由来のshape計算は共有する一つの正本にする。sourceの実frame数と元resize、参照画像の長辺上限848と16pixel単位のPython互換丸め、latent時間／空間圧縮、patch化、context順、token連結、source_idを含める。shape計算・数値演算・mappingの正本を重複させず、各moduleの単独利用を維持する。

ロード済み実体の確認と構成変更時の失効は内部化する。通常のデータ受け渡しに、利用者がsource・build・kernelの証跡を添付する方式を要求しない。取消・古い結果の不採用・解放を維持する。

今回の完了範囲は、既知の対応shapeでの通常実行、具体的理由による非対応判定、取消、解放まで。既存の数値参照は変更検証の診断側だけで利用する。実装をGitHubへpushし、固定SHA・API差分・通常実行結果・残るshape制限を報告する。詳細な数値証拠は診断資料に分離する。
