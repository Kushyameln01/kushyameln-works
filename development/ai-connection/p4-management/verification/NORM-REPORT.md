2026-11-02 JST. Implemented only the Task 1 files from the actual `p4-management/SPEC.md` and `PLAN.md`. No native/model execution, reference generation, mathematical operators or layer mapping were added.

The independent P4 catalog authenticates the historical six-file parent by provenance and preserves the parent records while adding P4 shape/EXEC and two finite norms. Its final pin is `e64e2e338b3a33ab2ea5521df652cb041a9d4033cec5da7e0f18d9c2373e023e` (9,601 bytes). The historical parent catalog, its six registered files, and the old N2 candidate's four files are byte-identical to HEAD; exact observed hashes are in `freeze-hashes.json`.

`declarations.mjs` exports the PLAN's profile/policy/record IDs, P4_PINS, P4_CATALOG_REF, P4_OUTPUTS, p4OutputSpecs, and prepareP4NormInputs. Additional caller conveniences are P4_GATES, P4_FIXED_DECLARATIONS, P4_TRUSTED_INPUTS, P4_CONDITIONING_CASES and P4_FIXTURE_REFERENCE_REFS. p4OutputSpecs accepts integer L=1..512 and derives only shapes. All 25 saved meanings are explicit management sidecars (`works:p4-output:<name>:f32`, `meaningAuthority:management-sidecar/owner-named-output`, `ownerNativeMeaning:null`). Output alias is excluded. The L512 shape sum is 63,709,184 bytes; this is a static extent, not a measured runtime peak.

`source.mjs` exports P4_FILES, verifyP4CrossFfnSource({files}) and isVerifiedP4CrossFfnSource. P4_FILES is 50 actual build dependencies plus the separately pinned owner common.compare source. Build50 refs identify execution5744; common.compare identifies distribution7ee. Source snapshots occur before the first digest await. The proof is WeakSet-branded, has no success boolean, rejects missing/changed bytes, and does not authenticate injected function origin, model data or a numerical result. Metadata277 is recorded separately.

prepareP4NormInputs returns the edgeInput itself. It requires caller observations in binding (owner/session/binding/generation plus sourceRef/buildId/kernelDigest/byteLength/bridgeWasmSHA256/attentionWasmSHA256), standard target/local revisions, managerSourceRef, conditioningMetadata, savedInputBindings and resourceState. It snapshots ordinary finite JSON, preserves opaque extension envelopes, and leaves missing source observations null. It never creates current evidence. conditioningMetadata is the separate manager JSON binding from P4_CONDITIONING_CASES, not the native recognized capture or its raw typed metadata.

The only compatibility judge remains evaluateEdge. New N-P4-SHAPE/N-P4-NUMERIC finite comparisons check the source, numerical profile, 25 shapes/sidecar fields, HIGH/LOW schedule and saved inputs, and conditioning cohort. Missing required contracts/bindings stay UNVERIFIED. Known mismatches are INCOMPATIBLE. Known matching declarations without numerical references/PASS remain COMPATIBLE / NOT_VERIFIED / BLOCKED. Fixture references retain their exact existing public receipt/payload hashes and cannot authorize nativeText even after labels are changed. Their outer reference and gate IDs are source-based git URIs explicitly marked `management-sidecar-for-exact-owner-source-bytes`; these labels are not owner API arguments or claimed owner exports.

P4 numericRequirement uses the existing envelope with explicit ownerSourceRef/kernelDigest/gateRef/referenceRef. referenceRef binds source/hash/bytes/ID, side/block/schedule/inputClass/textRows, conditioningBinding/savedInputBindings, and local/composed receipt+payload identities. The nativeText path additionally requires a separate pre-existing priorOwnerPass declaration with exact profile/source/build/cohort/reference/gate, 25 output hashes and 29 parameter checks. Prior declarations are never copied into current evidence; actual validation still belongs to createNormExecution.validated after an actual run. No actualText reference, hash, gate result or PASS is filled in by defaults.
