## Task1 — explicit external diagnostic adapter (TDD)

Own docs/shared/inference/lora/diffusion-diagnostic-adapter.mjs and tools/ai-connection/test-diffusion-diagnostic-adapter.mjs. Factory `createDiffusionDiagnosticAdapter({consumer,baseProvider,isOwnerCurrent})` consumes a real native consumer with describe/createSink/prepareLoad/validate/commit/rollback/prepareBase/releaseCandidate/run. Returns `{registry,baseProvider,createSink(plan),targetForPlan(plan,{x,expected,tolerance}),finalize(plan),restoreBase({x,expected,tolerance,signal,isCurrent}),run({x,signal}),describeBinding()}`. No import of peer private modules into product; caller injects native public objects. Adapter owns only its wrappers/candidate history; caller owns native consumer/stage/provider.

- Native registry shape is selected tile; v2 registry.shape is original full shape; convert native row-slice into explicit diagnostic bounds and preserve full native descriptor/hash in adapter sidecar. Binding names remain native weight(runtime-input) and bias(hike-parameter). Keep native and v2 registryHash separate. Validate native profile, shapes, identities, row count16, all columns and exact binding. LoRA loaderPolicyId is fixedcomfy policy. SDK boundary transform identity describes F32 original-coordinate values, not a claim that storage is unquantized or unsliced.
- Provider verifies v2 context three hashes, translates full original element offset/count into native selected offset/count, range checks, injects native hash and passes abort.
- createSink(plan) binds immutable plan/source/side/coverage/hash. Convert full offsets/fullShape/binding into native selected offset/shape. Detail has no bias patch: finish explicitly reads immutable base bias16, checksums and writes it as unmodified pass-through; record separately, never fabricate an adapter patch. Light bias is mandatory and is never auto-filled if missing. Native sink enforces extent/checksum/duplicates. Opaque handle wrapper binds native handle and exact plan.
- targetForPlan forwards scoped native validation with fixed x[5120], independent expected[16], tolerance; receipt retains original native evidence and adds exact v2 plan/hash/scope. Native commit success returns v2 CONSUMER_APPLIED for diagnostic only, with independent-copy owner proof tied to actual native candidate copy. generationReady remains false in SDK. Reject any bool/full/generation claim. Capture contexts and numeric inputs before awaits.
- Keep native candidate rollback history through SDK post-commit checks; finalize(plan) releases history only after caller observes completed stage. On failure SDK rollback must reach original candidate/context; old rollback cannot overwrite a newer epoch. Native copies retain session bytes after prepared release.
- restoreBase uses peer public prepareBase→validate→commit with native PARTIAL scope and explicit reference; validates same side/owner/current, releases candidate metadata after success and rolls back on failure. This is diagnostic side restoration, not a new SDK detach or common snapshot.
- Tests run actual pinned peer native consumer module under DIFFUSION_SOURCE_ROOT (path to peer repo subset), with explicitly synthetic provider/stage only for contract tests. Tests distinguish those fixtures from real base/ORT joint trial. Test nonzero selected row mapping, detail pass-through, light bias missing, wrong hash/binding/shape, missing/duplicate/checksum blocks, cancellation/current/old rollback, copied bytes after release, base restore/reapply and v1 refusal.
