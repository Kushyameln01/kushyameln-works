# Private bounded input-index prototype

This directory implements plan 1.2 §8.1. It is outside `docs/`; no public runtime imports it. It is an experimental, explicitly selected Mediabunny 1.61.5 demuxer adapter. The current public path, file limits, input acceptance and OPFS-free behavior are unchanged. Do not interpret its Node results as browser, native codec, 5–10 GB, save-dialog or headset qualification.

## Contract and fixed build

`make-patch.py` generates one patch to `src/isobmff/isobmff-demuxer.ts` at upstream commit `0664a57bf2f40e5c4efa176c75ebf1d60df69eb8`. The original/patched source and patch SHA-256 are in `patch-provenance.json`. Modified source retains MPL-2.0 attribution. `tools/vr180/build-input-index.mjs` first requires the unchanged vendor's exact byte reproduction using the existing build gate and esbuild 0.25.1. Only then does it apply hash-checked patches. The optional `--combined` applies the disjoint output muxer/boxes/source-close patch followed by this input demuxer patch and produces **one** bundle, `mediabunny-input-output-index.mjs`. Do not mix Input, Output, Source, Sink or EncodedPacket classes from different bundles within one conversion.

```js
const budget = createIndexBudget();
const inputIndex = await createInputIndex({
  source: blob, root, jobId: `${trialId}-in`, signal, budget,
  // If outputIndex is already alive during input initialization:
  sortBytes: 4 * 1024 ** 2 - OUTPUT_PROFILE.sortReservedBytes,
});
const outputIndex = await createOutputIndex({
  root, jobId: `${trialId}-out`, signal, budget,
});
const input = new sameBundle.Input({
  source: new sameBundle.BlobSource(blob), formats: [sameBundle.MP4],
});
input._vr180InputIndex = inputIndex; // Before any metadata/track request.
const format = new sameBundle.Mp4OutputFormat({fastStart: false});
format._options.vr180Index = outputIndex;
// Construct Output, packet sinks/sources and packets from sameBundle too.
```

Both controller IDs must be distinct, contain only ASCII letters/digits/`_`/`-`, and be at most 64 characters including suffix. Both use native Web Locks with the shared name `vr180:index-job:<controllerJobId>`. Same-ID input/output attempts fail before owning or removing the other directory. Native Web Locks and SyncAccessHandle are required in a DedicatedWorker; unavailable facilities are an explicit failure/BLOCKED result, never an in-memory fallback. Supplying the Node backend or test lock manager is only a local-test mechanism.

Always call `Input.dispose()` when finished, cancel an unfinished Output, then await both index controllers' `dispose()` in `finally`. Each removes only its owned directory. If close/remove fails, keep the controller (or initialization error's `retryCleanup`) and retry: its lease and cleanup ownership are intentionally retained. Do not claim cleanup from a requested cancel alone.

The fixed demuxer's packet/sink APIs are already asynchronous. The patch awaits the adapter at metadata, packet-by-time, key-packet, next-key and sample-info call sites. Calling its old synchronous full-table getter while this adapter is selected throws `PRIVATE_INPUT_SYNC_TABLE_ACCESS`; a Promise is not disguised as an array. Other formats and the unselected original MP4 branch remain unchanged. Input indexing initializes once; seeking or duration lookup does not rebuild it. Failed initialization is disposed, not silently retried against a partly built index.

## Representation and limits

The **unchanged public** strict range inspector validates all original boxes and table extents before indexing by default. A separately named `fixedMuxerFixture: true` option is only for comparison fixtures generated by the pinned muxer; it uses the private output-inspector extension for its checked signed-ctts `cslg` summary. The comparison CLIs require explicit `--fixed-muxer-fixture` for these inputs, and the option plus `metrics.validationProfile` is recorded. Default-mode cslg rejection and opt-in labeling have a regression test. The actual private WebCodecs entry must leave this option false and retain the public strict preflight. This does **not** extend public input acceptance. AAC roll/prol seek groups are not newly regenerated by this work.

A two-pass scan makes one bounded **small metadata** skeleton, copying codec/edit/description boxes while omitting sample/timing/chunk/key tables. All source table positions still refer to the original Blob. The original parser reads this skeleton; retained codec/metadata subviews are detached so they do not retain the whole skeleton. Original edit-list adjustment is retained. The demuxer's `moovSlice`, sampleTable and sampleTableByteOffset are not retained after initialization.

The input adapter reads `stsz`, `stsc`, `stco`/`co64`, `stts`, `ctts` and `stss` in pages. It writes 64-byte sample records containing source offset/size, decode ticks, presentation ticks, original duration, key flag and chunk extent. With ctts, an in-place heapsort and bounded external merge create stable `(PTS, decodeSampleId)` records and an 8-byte per-sample inverse rank on disk. Equal PTS ordering and the last presentation sample's original duration follow the pinned implementation. Lookup uses paged binary search; key lookup uses the original presentation/decode ordering rules. No sample-sized PTS, sorted-ID, inverse-ID, chunk or timing array is created.

| Explicit limit | Value |
| --- | ---: |
| Shared index buffer reservations | 8 MiB total |
| Source table page / IndexStore page | 64 KiB |
| Sort workspace | At most 4 MiB total across simultaneously alive controllers |
| Merge fan-in | 8 |
| Input tracks / combined sample count | 2 / 100,000 |
| Owned input stores / pending adapter operations | 12 / 8 |
| Small metadata skeleton / detached description bytes | 16 MiB each |
| Original source boxes / recursion | 20,000 / 16 |

The combined harness assigns input sorting `4,194,304 − 1,600,000 = 2,594,304` bytes while the output sort reservation is alive. Alternatively, finish input initialization before allocating output sorting. A separate budget for each controller does not satisfy the combined contract. Budget exhaustion is an explicit error with owned cleanup; no fallback arrays are built.

Small metadata is separately bounded and reported; it is **not included** in the 8 MiB index-buffer claim. `maxSkeletonBuildBytes` conservatively counts the skeleton, one page and detached descriptions while they coexist. JavaScript objects/strings, BlobSource cache, codec/GPU memory, native handles, OS cache and garbage collection are not covered by that index budget. Object-node and box counters also have explicit limits. These local reservations do not prove a browser-wide heap maximum.

`metrics` records table requests/max request bytes, cache misses, inspector reads, skeleton/description size, sort passes, store read/write bytes and extents, owned stores, queue peak and shared budget peak. Runtime packet payload reads remain Mediabunny BlobSource's responsibility, distinct from these index range logs.

## Local evidence and remaining acceptance

`evidence-2026-10-17.json` preserves build results and complete local comparison reports; `node-tests-2026-10-17.txt` preserves the focused test output. These are local working-tree snapshots with file hashes, not a deployed commit assertion.

- Unchanged vendor rebuilt byte-for-byte; input-only and combined fork builds passed with fixed esbuild 0.25.1.
- Input-only: three AVC+AAC fixtures using the unchanged public admission profile (465 packets), and explicitly opted-in pinned-muxer fixtures with monotonic/alternating-ctts × 5,000/25,000/100,000 samples (260,000 packets). Every packet payload, metadata and side data, decoder configuration, duration, EOF and selected seek/key queries matched the unchanged module.
- Combined: the same three small fixtures and both 100,000-sample patterns. A single fork bundle supplied both Input and Output; both adapters shared one budget and distinct owned IDs. Reference and candidate full-file length/SHA-256 matched, followed by unchanged-parser full-packet comparisons (200,465 packets). Maximum explicit shared reservation was 4,989,240 bytes; simultaneous sort reservations were 4 MiB.
- Fourteen focused tests cover an stsc 12-byte row crossing 64 KiB, co64, all 6,000 synthetic mappings, equal/negative-PTS multi-generation merge/inverse, short I/O, cancellation during table writing/merge/queued queries, eight-request backpressure, same-ID cross-controller conflict, budget failure, cleanup failure/retry, independent owner cleanup after failures, constructor failure after controller creation, default cslg rejection/fixture opt-in and missing native lease. This is a Node file/test-lock backend, not OPFS validation.

Every final comparison case records runtime source SHA-256 both before and after execution and fails if they differ. This includes both controllers, presentation index, shared store, public/private parsers, test backend, original distribution and comparison harnesses. A bundle hash alone would not identify these external modules. Cleanup attempts every owner even when an earlier cancel/dispose/close fails, and reports aggregated failures.

The final harness-only correction moved Input construction and hash I/O inside the already-owned controller's cleanup scope. Its deliberate invalid-module failure test verifies the job directory, handles, locks and reservations are cleared. Normal input-only and combined small fixtures were rerun as `p4-input-cleanup-public-3` and `p4-combined-cleanup-public-3`. The larger `*-fixtures-2` comparisons remain evidence for their recorded earlier harness hashes; controller, presentation index, parser and fork bytes were unchanged by this cleanup correction. Their allocation/media conclusions were not relabeled as reruns of the later harness.

Input-only metadata skeleton sizes were 569 bytes (monotonic) and 601 bytes (ctts) at all three sample counts. Table read requests never exceeded 65,536 bytes. Input-only reservation peaks were 332,160 bytes and 4,919,608 bytes respectively. These measurements demonstrate the tested index allocation behavior, not performance superiority or decoded media quality. The 100,000-sample input-only sample store read totals were 15,318,272 bytes (monotonic) and 12,959,488 bytes (ctts), including seeks; I/O costs are not hidden by the memory claim.

Earlier `p4-combined-small-1` / `p4-combined-counts-1` files matched, but the two simultaneously reserved sort areas totaled 5,794,304 bytes, exceeding the plan's 4 MiB sort allowance. Those trials are retained as superseded evidence and excluded from acceptance. The corrected `p4-combined-sortbudget-1` trials replaced them; final `p4-input-public-2`, `p4-input-fixtures-2`, `p4-combined-public-2` and `p4-combined-fixtures-2` additionally record explicit admission profiles and start/end runtime hashes. Earlier controller comparisons used the private parser implicitly and are not evidence for the final default admission behavior.

Still unverified here: combined native OPFS/Web Locks execution, WebCodecs pixel transformation and audio playback, browser process memory/latency, external save/cancel dialogs, long real footage, 5–10 GB processing/recovery, final VR metadata and headset behavior. The root task owns the native conversion and independent verification gates; no public release follows from this directory's local PASS results.
