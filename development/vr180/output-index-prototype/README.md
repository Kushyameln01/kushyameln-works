# VR180 output-index private prototype — work in progress

This source is outside the Pages `docs/` tree and is not imported by the public product. It does not change the 100,000 combined-sample, 1 GiB conversion-output or existing metadata limits. The public OPFS-less direct path is unchanged. Input indexing (P4), VR player acceptance, decoded image/audio acceptance and 5–10 GB media qualification remain outside this prototype's completed claims.

## Fixed source and reproducible fork

The three-file patch targets Mediabunny 1.61.5, upstream commit `0664a57bf2f40e5c4efa176c75ebf1d60df69eb8`, using the existing source tarball SHA-256 `95c03a00ca69a7d5ed9805e424349ffeb0cdecbe8cabd0e17749a39e8117802f`. `patch-provenance.json` binds each original and patched file and the patch. `make-patch.py` recreates the patch from that exact source and refuses changed textual contexts. The upstream license and source remain at `docs/shared/media-basic/vendor/mediabunny-LICENSE` and `mediabunny-1.61.5-source.tgz`. Changed upstream source and the derived controller remain MPL-2.0; upstream notices are retained. This is not a change to the shared vendor.

`node tools/vr180/build-output-index.mjs --esbuild-dir <isolated exact 0.25.1> --output-dir <new directory outside repo>` first runs the unchanged-core byte-reproduction gate. Only PASS permits applying the checked patch and building with the identical core options. It writes a separate `mediabunny-output-index.mjs` and `fork-build-result.json`. The output directory must not exist. See `../build-inputs/README.md` for fixed-lock acquisition. Dependency acquisition is not hidden in this runner.

The patch adds an explicit private `format._options.vr180Index` adapter, not a public API. Only classes from the fork bundle may create the candidate Output, source, packets and target. With no adapter the old code path remains; this does not make old-path large-memory behavior a fallback for adapter failure.

## Private profile and ownership

`createOutputIndex({root, jobId, signal, layout})` acquires the native origin/storage-bucket Web Lock `vr180:index-job:<jobId>` (shared with the input-index controller) before checking/creating its job. `layout` is `null` for exact untagged baseline comparison, or `sbs` / `tb` to insert the existing product's VR180 metadata values. Only nonfragmented `fastStart:false`, H.264 with zero/one AAC track is intended. Call `dispose()` in an independent owner finally block, even when upstream `Output.cancel()` throws. An internal AbortController forwards external cancellation into both IndexStore and metadata inspection; `dispose()` aborts it before awaiting active work; it cancels pending controller work, waits for it, closes all owned index and metadata handles, removes only that job, then releases the lease. Cleanup failure retains ownership for retry. No browser in-memory lock fallback exists. Node's injected adapter and LockManager are tests only.

Samples are fixed 64-byte records (float64 PTS/DTS/duration/delta/offset; uint32 size/key; int32 composition offset; little endian). Chunks are 24 bytes (float64 offset/count/start PTS). Final table stores use fixed 4/8/12-byte records. Unresolved timestamp records stay on disk and are patched after sorting timestamp values. Only one pending stts/ctts/stsc run is retained while final tables are generated.

The private profile retains the current combined 100,000-sample ceiling. Its timestamp workspace reserves 1,600,000 bytes: one fixed-capacity 800,000-byte Float64 buffer plus conservative sort-work allowance. It is part of the shared 8 MiB explicit index budget and below the 4 MiB sort allowance. It is **not** an external sort implementation and cannot justify lifting the sample ceiling. Runtime-internal sort allocation, JS objects, codec/native memory, original reference implementation and OS cache are not measured by this reservation.

Original half-second chunk boundaries and track write ordering are preserved. A live chunk is limited to 4,096 sample references, 4 MiB payload, and 4 MiB conservatively counted backing allocations per track. Every borrowed view counts its entire ArrayBuffer, including repeat references to one buffer; a 6,744-byte view into an 8 MiB buffer is explicitly refused before retention; exceeding either explicitly fails this private profile, rather than changing chunk layout silently. Payload bytes are separately bounded and reported, not included in the index-buffer budget. Writer output is fed/awaited in at most 64 KiB pieces. Private harness entry points fix StreamTarget to 1 MiB chunks and WritableStream HWM=1; arbitrary caller target settings are outside this bounded claim. Writer flush is not equivalent to physical sink acknowledgement. Source packet arrays and upstream target allocations are separately observed. These are trial limits, not new public supported limits.

## Incremental metadata and commit boundary

Small codec/movie box generation is reused from the fixed source. Table leaves are disk-backed descriptors. Box sizes are counted first and emitted as headers, small contents and table pages; there is no whole-moov concatenation or `onMoov` tracking. Each emitted byte also goes to the job's metadata spool, with partial-write progress checking and task yields. The spool must match its counted extent, flush, close, and produce a matching-size File before parser use.

The private output-only `inspectMp4` derivative receives only ftyp, actual mdat header and the finalized metadata File at their real output offsets. Missing payload ranges are rejected, not zero-filled. VR tags, when requested, are included before this validation. The controller never commits the external destination. The caller may commit only after Output.finalize and this verification succeed; saved-file readback/hash and independent recovery remain separate requirements. Node comparison files are real test files but not transactional browser picker saves.

## Narrow private cslg recovery

The latest patch also fixes `media-source.ts` closing-error propagation: await the asynchronous muxer track close, and observe the original retained closing promise without replacing it. Before this fix, three injected index close failures produced unhandled rejections and one cancel incorrectly resolved. After the fix, all three original errors reach finalize/cancel, pending close is awaited and unhandled count is zero. The muxer/box calculation patches are unchanged. The new output bundle SHA is `5c97e2e45a2e4d4ac659f6574c3862182fe541a36fc861d80f171eb3cd3f8023`; combined bundle SHA is `65a96894f5442fe92d3672e09b80e6841b7a30a745b002b071636352f5b790cd`. Previous native evidence identifies the older bundle and is not relabeled. See `../evidence/2026-10-17-source-close-recovery.json`.

The fixed original muxer's alternating-ctts output contains `cslg`, which the public input parser intentionally refuses. Dropping the box, skipping validation, or permitting arbitrary unknown boxes would invalidate the comparison. `make-private-parser.py` therefore makes a hash-bound output-only copy; `parser-provenance.json` and `mp4-output-inspect.patch` preserve the exact public base and narrow delta. The public parser is unchanged.

This private profile accepts only one exact-length version-0/zero-flags `cslg` alongside signed version-1 `ctts`. All five signed summary fields must equal independently traversed sample timing: shift, least/greatest offset, presentation start/end. Changed fields, flags/version, duplicates and unknown boxes are refused. This is a pinned-source contract, not general historical QuickTime semantics. Primary references: [MP4 registration authority](https://mp4ra.org/registered-types/boxes), [Apple composition shift least greatest atom](https://developer.apple.com/documentation/quicktime-file-format/composition_shift_least_greatest_atom), and fixed upstream `isobmff-boxes.ts` `cslg` implementation. Metadata payloads remain independently parsed before any external commit.
