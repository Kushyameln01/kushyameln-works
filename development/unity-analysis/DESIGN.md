Resource detail for 1.2 review: a single archive expansion task must fit the existing 16 MiB pool input budget (per archive <=16 MiB; selection total <=32 MiB). Expansion returns at most64 MiB of owned file bytes; this result is consumed immediately and not retained in the pool. The pool's 8 MiB retained-results budget is an eviction budget, not a process-memory promise. At most four parse tasks (each <=4 MiB input) run concurrently; output IR still <=4 MiB per snapshot and report <=8 MiB. No hidden truncation; excess cancels the session with a named limit. Copy the reviewed read-only package implementation into the Unity adapter with a 64 MiB incremental decompression bound, preserving FT's original 128 MiB contract unchanged. Peak temporary allocation and UTF-16 string cost are acknowledged separately from logical bounds.

1.2 result ownership: expansion uses an explicit delivery-only task result policy. The Worker transfers owned ArrayBuffers; `finish` resolves the task without adding its data to retained results or evicting any other caller results, and removes only its own terminal record. `getResult` is intentionally unavailable for delivery-only stages; the SDK consumes the Promise result immediately and releases stage buffers. Existing retained tasks preserve their behavior. Input byte snapshots belong to the task and are transferred only after admission.

1.2 derived limits: check before allocation/insertion; `DIFF_PAIR_LIMIT` = 262144, `OWNER_CONTEXT_LIMIT` = 262144, `GRAPH_STEP_LIMIT` = 2000000. Each kernel vector must independently meet its 262144 limit. A named failure cancels the session rather than omitting entries or claiming complete coverage.

1.2 text API: `parseUnityFile({path,text})` returns `{path,objects,coverage,reason?,issues,meta?}`. Each issue contains `{code,message,source,relatedSources?,propertyPath?}`. Source offsets start/end are UTF-16 code-unit offsets (zero-based, end-exclusive); line/column are one-based. Machine paths are RFC6901 JSON Pointers (display paths may differ). Duplicate mapping keys retain both positions in an issue; the affected document produces no confirmed rules/references (never last-wins). Duplicate document fileIDs remain separate objects. Declarations carry `domain` (`animator`/`vrchat-expression`) and optional verified `schemaIdentity`; Expression declarations require the known script GUID/fileID. Uses remain unowned until the complete graph provides scope. Actual raw-byte hashes belong to ingestion, not the text parser.
