1.2 result ownership: expansion uses an explicit delivery-only task result policy. The Worker transfers owned ArrayBuffers; `finish` resolves the task without adding its data to retained results or evicting any other caller results, and removes only its own terminal record. `getResult` is intentionally unavailable for delivery-only stages; the SDK consumes the Promise result immediately and releases stage buffers. Existing retained tasks preserve their behavior. Input byte snapshots belong to the task and are transferred only after admission.

1.2 derived limits: check before allocation/insertion; `DIFF_PAIR_LIMIT` = 262144, `OWNER_CONTEXT_LIMIT` = 262144, `GRAPH_STEP_LIMIT` = 2000000. Each kernel vector must independently meet its 262144 limit. A named failure cancels the session rather than omitting entries or claiming complete coverage.

1.2 text API: `parseUnityFile({path,text})` returns `{path,objects,coverage,reason?,issues,meta?}`. Each issue contains `{code,message,source,relatedSources?,propertyPath?}`. Source offsets start/end are UTF-16 code-unit offsets (zero-based, end-exclusive); line/column are one-based. Machine paths are RFC6901 JSON Pointers (display paths may differ). Duplicate mapping keys retain both positions in an issue; the affected document produces no confirmed rules/references (never last-wins). Duplicate document fileIDs remain separate objects. Declarations carry `domain` (`animator`/`vrchat-expression`) and optional verified `schemaIdentity`; Expression declarations require the known script GUID/fileID.
