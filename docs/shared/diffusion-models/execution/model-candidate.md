# Experimental full Bernini graph

`model-candidate.mjs` contains a complete base-model prediction graph, separate
as a reusable numerical owner. It remains experimental: its internal `acceptedProduction`,
`generationReady`, and `publicRuntimeEnabled` metadata remain false. The public Worker now
routes to this owner through the fixed [adapter](../api/MODEL_RUNTIME.md); the outer
`publicWorkerConnected:true` flag records routing, not shape or precision acceptance.
This file does not establish full-target D2 acceptance.

```js
const candidate = await createBerniniModelCandidate({file, side: 'LOW'});
try {
  const velocity = await candidate.predict({
    shapeRequest, tensors, conditioning, timestep: 500, signal, onProgress
  });
} finally {
  await candidate.dispose();
}
```

Preparation also accepts actual `source`, `math`, and `ops` operator owners for
environments which prepare them separately. Supplied owners remain caller owned.
They must implement the original identified 1095-target source and all native
Hike/ORT arithmetic methods, including `divideAttention`; there is no predictor
callback or output substitution entrypoint. Default preparation uses an immutable
Blob, explicit HIGH/LOW side, pinned header/size verification, F16 or scalar-scaled
E4M3FN decoding, Hike model math, and ORT full-inner Gemm and online attention.
Owned source preparation defaults to `decoder: 'lookup'`, using immutable tables
generated by the existing Hike decoder as its numeric oracle. `decoder: 'legacy'`
selects the original direct decoder. Optional `lookupBytes` are captured before
the first await, like `bridgeBytes` and `mathWasmBytes`. The underlying weight
source retains its own default of `legacy`; supplied sources choose their decoder
before candidate construction.
Header identification does not recompute the original 15.6 GB file's full hash.

Input `shapeRequest` and ordered target/context `tensors` use
`createModelSequence` and the shared `deriveWorkflowShapes` rule. This candidate
requires batch 1, native `float32`, 16 latent channels, patch [1,2,2], complete
context population, and even spatial latent dimensions. It uses the canonical
target meaning `bernini-generated-model-latent:v1`, context meaning
`wan21-normalized-posterior-mean:v1`, and normalization
`wan21-comfy-f32-v1`. It does not normalize input values again.

Allocation admission has a conservative planning cap of 90,000 total sequence
tokens. Requests above it fail with `code: 'RESOURCE_BUDGET'` after canonical
sequence validation and before prefix weight reads or hidden-store allocation.
The error names all four planned host hidden stores. At the cap each N×5120 F32
store is 1,843,200,000 bytes, below the exclusive 2 GiB per-array bound; the four
stores total 7,372,800,000 bytes. These are named span estimates, not measured
peak memory or an accepted production domain. Operator snapshots, caches and
allocator overhead remain additional. The 87,992-token target/source plus eight
848-pixel reference-image shape is inside this planning cap; its native execution
and numerical acceptance remain unverified.

`conditioning` is a native Text descriptor with compact finite Float32 `data`,
shape [1,L,4096] for 1..512 rows, `dtype: 'float32'`, `layout: 'BLC'`,
`meaning: 'text_hidden_states'`, `normalization:
'umt5-final-rmsnorm-f32-v1'`, the known Text model/tokenizer SHA256 fields, and a
binary Uint8 attention mask. Existing native P4 ingress validates and snapshots
these fields synchronously before the first await. Masked Text input rows must
be zero. The mask is provenance: all L rows participate in cross-attention,
including the learned text projection of zero input rows. Declared provenance
does not authenticate execution of the Text producer. No payload hash or private
capture receipt is required. The timestep is one finite scalar in 0..1000.

The returned native tensor has `data`, target NCTHW `shape`, `dtype: 'float32'`,
`layout: 'NCTHW'`, `meaning: 'bernini-flow-velocity:v1'`, `space: 'model'`, model
SHA256, and experimental execution evidence. Its values are flow velocity in
Bernini model latent coordinates. A velocity is not a generated sample or VAE
posterior mean and must not be passed to sample restoration as either one.

The graph executes patch projection for every stream; Text projection
4096→5120→5120 with tanh GELU; sinusoidal256→5120 SiLU→5120 raw time embedding;
SiLU(raw embedding) and six independent 5120-output time projection chunks;
all 40 blocks; and the final head for **every** sequence token before retaining
the target prefix and unpatchifying it. Every dense layer includes its bias.
Each block uses parameter-free LN1 plus modulation, full-width Q/K RMSNorm and
self RoPE, global self attention, output projection and gated residual; affine
LN3 and full Text cross attention without RoPE or a softmax mask; then
parameter-free LN2/modulation, 13824-wide tanh GELU FFN and gated residual. The
head consumes the raw time embedding, not its SiLU or projected forms.

The storage schedule avoids a sequence-wide score matrix and full-sequence FFN:

* Self attention has four host stores of N×5120 F32: block input, block output,
  K, and V. K/V generation holds one 5120² weight at a time. The query/output
  stage caches its two 5120² weights; Q exists only for at most 128 rows.
* Each query tile visits all key tiles of at most 256 rows. ORT accumulates
  head-major online softmax numerator/denominator, Hike performs final division,
  and JavaScript only copies layout back to token-major rows.
* After self attention, its input/K/V become unreachable. Cross attention and
  FFN update the remaining hidden store in place. Text K/V are at most 512 rows.
* FFN-up caches three compact output chunks with 5120, 5120 and 3584 outputs;
  every chunk retains the full 5120 inner dimension. FFN-down has all 5120
  outputs and its full 13824 inner dimension. Their combined weight cache is
  566,231,040 bytes; the expanded activation exists for one 128-row tile.

All non-head model matrices are loaded once per prediction stage and reused for
all token tiles. The six time-projection chunks are each read once. No model
matrix is reread per token. The small existing head cache survives subsequent
predictions; other stage caches are released. Cancellation checks occur around
source reads and native calls, and failed predictions return no partial tensor.
`dispose()` cancels an active prediction, waits for its terminal cleanup, and
releases owned dependencies; `recover()` retries disposal after cleanup failure.
The cache is on the JavaScript host: ORT still snapshots weight inputs for every
tile. Execution evidence reports operator input/output copy byte deltas, so host
caching does not imply native weight residency or eliminate that memory traffic.
Named span statistics exclude transient operator snapshots, source decode
buffers, garbage collection latency, and ORT allocator memory. Aggregate peak
memory is unmeasured. No all-40-block weight cache or LoRA adapter application is
provided by this candidate.

The separate `diagnose(input, {onTrace})` method supplies an output-only hook
`onTrace({name, shape, data, dtype, profile, acceptedProduction})` for independent
numerical comparison. Normal `predict` rejects an `onTrace` field. The hook receives
owned copies named `patchHidden`, `textEmbedded`, `timeRaw`, `timeAct1`,
`timeProjection`, `block00Output` through `block39Output`, `headAll`, and
`prediction`. A promise returned by the hook is awaited so a runner can persist
private artifacts; its value is ignored and cannot replace a calculation.
Tracing is disabled by default and adds copies outside the named resource
statistics. `diagnose` permits at most 128 total sequence tokens; normal `predict`
retains the complete canonical sequence contract. Full intermediate values should
remain private. A trace callback can abort the supplied signal to cancel, but
must not await disposal of the same active owner from inside that callback.

`test-model-candidate.mjs` checks metadata admission, rejection, ownership and
cancelled loading using explicit nonnumeric doubles. It produces no synthetic
prediction and supplies no numerical full-model evidence. A small real all-40
run, when recorded, must be distinguished from the required full target/context
shape. Production precision parity and a native prediction with 65,520 total
tokens plus numerical comparison remain unverified. The resource report estimates
about 5 PFLOP per prediction; its throughput scenarios are not measured completion
times or a proof that execution is impossible. Public enablement remains blocked
until the required numerical and combined-resource evidence exists.

`model-candidate-browser.py` is a portable CLI for the frozen controlled N5/L3
case. It requires `--source-commit`, verifies every runtime JS/WASM dependency is
tracked and byte-identical to that commit, and rechecks sources, fixture, core,
contract and retained model stat after execution. The model enters Chromium via
`set_input_files`; the HTTP server serves committed public modules only. All47
trace values are written with mode 0600 in `diffusion-private-hidden` or a
dedicated temporary subdirectory with a mode0700 parent, outside all Git
checkouts. Public output and
progress JSONL contain identities, shapes, resource counters and timings only.

```bash
python docs/shared/diffusion-models/execution/model-candidate-browser.py \
  --source-commit COMMITTED_SHA \
  --fixture /private/standalone-n5-l3-input.json \
  --private-output /private/low-candidate.json \
  --output /path/to/metrics-only.json \
  --side LOW --models /path/to/retained/bernini
```

Use `--check-only` to perform the source/input guards without any native NN work.
Use `--stop-after-prefix` or `--stop-after-block 0` for an explicitly cancelled
timing probe; these save partial private traces and never claim a completed
prediction. `--chromium`, `--model`, `--contract` and `--core` override local paths.
The full diagnostic is still a controlled five-token experiment, separate from
the unverified 65,520-token workflow acceptance.
