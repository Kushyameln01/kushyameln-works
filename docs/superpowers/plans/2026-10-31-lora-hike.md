# Local-folder LoRA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Track steps below; independent source/kernel workers have exclusive file scopes.

**Goal:** Independent LoRA API using user-terminal local High/Low safetensors and actual Hike WASM calculation, ready for consumer integration.
**Architecture:** Local folder captures immutable original File references; catalog remains optional. Range provider validates bounded binary reads, planner covers all tensors against explicit target registry, Hike applies blocks into transactional consumer sink. Consumer loads prepared package, validates and commits snapshot.
**Tech Stack:** dependency-free browser ES modules, Node test runner, pinned Hike WABT normal, Chromium.
**Spec:** development/lora/IDEAL_STATE.md and SOURCE_PLAN.md.

## Global Constraints
- Revision2: local terminal folder input; no cloud upload/browser-persistent registration, publishing or backend substitution.
- High/Low mapping is fixed per category. Base immutable; prepare uses original base every time.
- External inference consumer/graph absent: report integration unverified; do not invent real model success.

## Review Focus
- Range ignored or remote file mutated: reject, bounded reads.
- Unknown/missing patch tensor: reject whole application before sink mutation.
- Changed selection during asynchronous work: stale job cannot commit.
- Unavailable WASM: error rather than JS fallback.
- Consumer switch failure: rollback prepared state, do not mix revisions.
