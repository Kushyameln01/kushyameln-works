Kushyameln Works
トップページAnimator Composer

ControllerとExpressionParametersをまとめ、Binary・Smoothの専用Layerと共通Maskを配置します。元のアセット名・GUID・内包Clipを保持し、Merged_DecodeAndSmoothフォルダーにまとめます。素材はブラウザ内で処理します。

1. 素材を読み込む

Controller・ExpressionParameters・Mask・2つのBlendTreeと、その参照素材を用意してください。

2. 統合する参照を指定

AnimatorController

上から順に統合します。先頭を統合先にし、そのファイル名・GUIDを保持します。

    ExpressionParameters

    最初に選択したExpressionを統合先にし、そのファイル名・GUIDを保持します。

      重複するLayer名

      既存Layerの重複名だけを調整してください。

      ExpressionParametersの型・同期規定

      BinaryParameters用：末尾が数字（0〜9）またはNegativeのParameterをBoolで登録し、同期ONにします。Animator側の型は保持します。

      Negative末尾のParameterは、元のParameterの公式値域が0〜正の数なら同期OFF、負の数〜正の数ならONにします。値域が不明なら、この規定では変更しません。Binary用規定の後に適用します。チェックを外すとBinary用規定のみになります。

      参照：VRCFT5 Parameter範囲 · Binary Parameters

      固定設定と対象Playable
      • 親フォルダー：Merged_DecodeAndSmooth
      • 既存ファイルのGUID・名前・内包構造を保持
      • 全LayerのWeight：1
      • 新設StateのWrite Defaults：ON
      • AlwaysOne：1（未登録ならFloatで追加）
      • v2/EyeLidLeft・v2/EyeLidRight・v2/EyeLid：0.75（完全一致する登録に適用）
      • Savedと、上記の同期規定の対象外にある同期設定は保持します。

      素材を選択してください。

      入力と設定を確認してください

        入力・出力と連携API
        参照素材と元のファイルパスを含むUnitypackageを読み込みます。アップロードしたファイル自体は変更しません。出力では既存GUIDを保持するため、UnityへのImport時は同じGUIDのAssetを更新します。同名Parameterの定義が競合した場合は、該当する入力を確認してください。
        全出力をAssets/Merged_DecodeAndSmooth/配下へ配置します。その下の元の階層・ファイル名と、BlendTree内のClip・GUID・fileID・metaを保持します。統合先ControllerとExpressionの必要項目だけを更新し、Installerは生成しません。
        統括ツールからは shared/animator-integrator/client.mjs の createAnimatorIntegrator() を利用できます。画面と同じWorker・統合処理を呼び出します。
